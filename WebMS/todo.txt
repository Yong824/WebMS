* Confirmed (Q&A):
	1. Can our project don't have HomeController, instead we use CustomerController and app.MapControllerRoute route to it?
		- No, keep the HomeController even if just one file in Views/Home folder

	2. Can we let the admin part be accessed by using url, localhost/admin, are admin and customer must use the same login page?
		- With the same login page, navigate user to admin if their account user role is admin.

	3. Where to store the services (methods) file, using controller then inject it in each of the page use of it? Or all in the same controller 
		(e.g. all admin page function stored in one AdminController.cs file? If so how about backend API like PaymentController)
		- Can have service file, but if possible try to make use of controller instead of service.

	4. Can I create sub-subfolder in the Views
		- No, one subfolder one Controller, try to avoid sub-subfolder. Which means just one level in the Views.
		- And thus, in each subfolder will have an Index.cshtml file. 
		- NOT DO:
			Views/Admin/Cinema/Cinema.cshtml
			Views/Admin/Hall/Hall.cshtml
			Views/Admin/Movie/Movie.cshtml
		- DO:
			View/Admin/Index.cshtml
			View/Cinema/Index.cshtml
			View/Hall/Index.cshtml
			View/Movie/Index.cshtml

	5. Can I create subfolder in Controller
		- No, just put all at the same level in the folder of Controllers

	6. Can I use Areas for the project
		- No, this project not so big, keep it as simple as possible

	7. No need [Required] attribute in the Models files.
	7.1 Nullable variable no need something like " = string.Empty", or "null!;", just use the question mark (e.g. public string? Name { get; set; })
	7.2 For List initialization, assign it with empty array (e.g. List<Product> Products  { get; set; } = [];)

	8. Use "StringLength" instead of "MaxLength" for the ViewModels files
		8.1 But in the Entities files keep them as "MaxLength"

	9. Not use "public List<SeatSchedule> SeatSchedules { get; set; } = new List<SeatSchedule>();"
		Instead, use "public List<SeatSchedule> SeatSchedules { get; set; } = [];"

	10. Database Relationship try do like full (two-way) navigation, example as:
			Inside class <Product> has Category object
			Inside class <Category> has List<Product> 
		If possible, NOT do like:
			Inside class <Product> has Category object
			BUT, inside class <Category> no have List<Product>

	11. No need attribute [ForeignKey(...)], just use the default naming conversion, for example
			public Guid CategoryId { get; set; }
			public Category Category { get; set; }
		The program will read the category id and auto assign to the category, as long as follow the format 
			"<objectVariableName>Id" (e.g. in this case objectVariableName = "Category")

	12. No need use attribute [ColumnType(...)]
			As long as you assigned the datatype, it will auto decide the column type for database
